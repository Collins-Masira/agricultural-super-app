# API Reference

All endpoints are prefixed with `/api`, except `/health`. All request and
response bodies are JSON.

This document was generated by exercising every endpoint against the
running application and capturing real responses — the example payloads
below are actual output, not hand-written approximations.

## Authentication

Protected endpoints require a JWT in the `Authorization` header:

```
Authorization: Bearer <token>
```

Tokens are issued by `POST /api/auth/register` and `POST /api/auth/login`,
and expire after `JWT_ACCESS_TOKEN_EXPIRES_SECONDS` (default 24h — see
`app/config.py`). There is currently no refresh-token flow or logout
endpoint; see `docs/TECHNICAL_DEBT.md` item 5.

## Error format

Every error response, from every endpoint, uses the same envelope:

```json
{
  "error": "A human-readable message.",
  "details": { "field_name": ["Why it failed."] }
}
```

`details` is only present for validation errors (HTTP 422). See
`app/errors.py` for the exception hierarchy.

| Status | Meaning | Raised by |
| --- | --- | --- |
| 401 | Missing, invalid, expired, or forged token; wrong login credentials; deactivated account | `UnauthorizedError` |
| 403 | Authenticated, but not allowed to perform this action (not the owner/creator/participant) | `ForbiddenError` |
| 404 | Resource does not exist | `NotFoundError` |
| 409 | Conflicts with existing state (duplicate username/email/name, already following/liked/joined) | `ConflictError` |
| 422 | Request body failed schema validation | `ValidationAPIError` / Marshmallow `ValidationError` |
| 500 | Unhandled server error (never leaks a stack trace) | global handler |

## Pagination

`GET /api/posts` and `GET /api/communities` accept `?page=<int>` (default
1) and `?per_page=<int>` (default 20, capped at 100 server-side
regardless of what's requested — see `MAX_PAGE_SIZE` in the relevant
service). Both list endpoints order newest-first by `created_at`.

## Auth

### `POST /api/auth/register`

No auth required.

**Request body:**

```json
{
  "username": "amina",
  "email": "amina@example.com",
  "password": "supersecret123",
  "role": "farmer"
}
```

`username` (3–50 chars), `email`, and `password` (min 8 chars) are
required. `role` is optional, defaults to `"farmer"`, and is restricted
to `"farmer"` or `"expert"` — **`"admin"` is deliberately rejected here**;
see `app/schemas/user_schema.py` for why.

**201 response:**

```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "id": 1,
    "username": "amina",
    "email": "amina@example.com",
    "role": "farmer",
    "is_active": true,
    "created_at": "2026-08-25T07:54:17.706426",
    "updated_at": "2026-08-25T07:54:17.706432",
    "profile": null
  }
}
```

`password_hash` never appears in any response, under any circumstance.

**Errors:** 409 (username or email already taken), 422 (validation, including a rejected `role`).

### `POST /api/auth/login`

No auth required. Accepts either `username` or `email` as the identifier.

**Request body:**

```json
{ "username": "amina", "password": "supersecret123" }
```

**200 response:** same shape as register's response.

**Errors:** 401 (wrong password, unknown identifier, or deactivated
account — all return the identical message, deliberately, to prevent
account enumeration). 422 (missing identifier or password).

### `GET /api/auth/me`

Auth required.

**200 response:**

```json
{
  "id": 1,
  "username": "amina",
  "email": "amina@example.com",
  "role": "farmer",
  "is_active": true,
  "created_at": "2026-08-25T07:54:17.706426",
  "updated_at": "2026-08-25T07:54:17.706432",
  "profile": { "first_name": "Amina", "last_name": null, "bio": "Maize farmer in Nakuru", "location": null, "profile_image_url": null, "phone_number": null, "created_at": "...", "updated_at": "..." }
}
```

## Users

### `GET /api/users/<id>`

No auth required. Public view — deliberately excludes `email` and every
account-management field (see `UserPublicSchema`).

**200 response:**

```json
{ "id": 2, "username": "brian", "role": "expert", "profile": null }
```

**Errors:** 404.

### `PUT /api/users/me/profile`

Auth required. Creates the caller's profile on first call, updates it on
every call after (partial updates supported — only send the fields
you're changing).

**Request body:** any subset of `first_name`, `last_name`, `bio`,
`location`, `profile_image_url`, `phone_number`.

**200 response:**

```json
{
  "id": 1,
  "user_id": 1,
  "first_name": "Amina",
  "last_name": null,
  "bio": "Maize farmer in Nakuru",
  "location": null,
  "profile_image_url": null,
  "phone_number": null,
  "created_at": "2026-08-25T07:54:17.927971",
  "updated_at": "2026-08-25T07:54:17.927973"
}
```

### `POST /api/users/<id>/follow`

Auth required. **201** `{"message": "Now following user.", "user_id": <id>}`.

**Errors:** 404 (unknown user), 409 (already following), 422 (following yourself).

### `DELETE /api/users/<id>/follow`

Auth required. **204** (empty body).

**Errors:** 404 (not currently following this user).

## Posts

### `GET /api/posts`

No auth required. `?page=`, `?per_page=`. **200**: array of posts (same
shape as the create-post response below).

### `POST /api/posts`

Auth required.

**Request body:**

```json
{
  "title": "Maize planting tips",
  "content": "Plant in rows 75cm apart.",
  "images": [{ "image_url": "https://example.com/maize.jpg" }]
}
```

`title` and `content` are required. `images` is optional — only
`image_url` is read from each entry; any other key sent is silently
ignored (see `PostImageSchema`).

**201 response:**

```json
{
  "id": 1,
  "user_id": 1,
  "title": "Maize planting tips",
  "content": "Plant in rows 75cm apart.",
  "created_at": "2026-08-25T07:54:17.934924",
  "updated_at": "2026-08-25T07:54:17.934927",
  "author": { "id": 1, "username": "amina", "role": "farmer", "profile": { "first_name": "Amina", "last_name": null, "profile_image_url": null } },
  "images": [{ "id": 1, "post_id": 1, "image_url": "https://example.com/maize.jpg", "created_at": "..." }],
  "comments": []
}
```

**Errors:** 401, 422 (missing title/content).

### `GET /api/posts/<id>`

No auth required. **200**: full detail, same shape as above. **404** if unknown.

### `PUT /api/posts/<id>`

Auth required, owner (or `role == "admin"`) only. Partial update — send
only the fields you're changing. An `images` key in the body is
deliberately ignored (see the code comment in `post_service.update_post`
for why) — use the dedicated `/images` endpoints below.

**200**: updated post. **Errors:** 401, 403 (not the owner), 404.

### `DELETE /api/posts/<id>`

Auth required, owner (or admin) only. **204**. **Errors:** 401, 403, 404.

### `POST /api/posts/<id>/images`

Auth required, owner only. Body: `{"image_url": "..."}`.
**201**: the created image. **Errors:** 401, 403, 404 (unknown post), 422 (missing `image_url`).

### `DELETE /api/posts/<id>/images/<image_id>`

Auth required, owner only. **204**.
**Errors:** 401, 403, 404 (unknown post, or the image doesn't belong to that post).

### `GET /api/posts/<id>/comments`

No auth required. **200**: array of comments. **404** if the post doesn't exist.

### `POST /api/posts/<id>/comments`

Auth required (any authenticated user, not just the post's author).
Body: `{"content": "..."}`.

**201 response:**

```json
{
  "id": 1,
  "user_id": 2,
  "post_id": 1,
  "content": "Great tips!",
  "created_at": "...",
  "updated_at": "...",
  "author": { "id": 2, "username": "brian", "role": "expert", "profile": null }
}
```

**Errors:** 401, 404 (unknown post), 422 (missing `content`).

### `POST /api/posts/<id>/like` / `DELETE /api/posts/<id>/like`

Auth required. **201** `{"message": "Post liked."}` / **204**.
**Errors:** 401, 404, 409 (already liked), 404 on unlike if not currently liked.

## Comments

Editing/deleting a specific comment is addressed by its own id, not
nested under its post — matches how `/api/posts/<id>` itself works.

### `PUT /api/comments/<id>`

Auth required, comment author (or admin) only. Body: `{"content": "..."}`.
**200**: updated comment. **Errors:** 401, 403, 404, 422 (missing `content`).

### `DELETE /api/comments/<id>`

Auth required, comment author (or admin) only. **204**. **Errors:** 401, 403, 404.

## Communities

### `GET /api/communities`

No auth required. `?page=`, `?per_page=`. **200**: array of communities.

### `POST /api/communities`

Auth required. Body: `{"name": "...", "description": "...", "image_url": "..."}`
(`name` required, unique). The creator is automatically added as the
first member.

**201 response:**

```json
{
  "id": 1,
  "name": "Maize Farmers KE",
  "description": "For maize growers",
  "image_url": null,
  "created_by": 1,
  "created_at": "...",
  "updated_at": "...",
  "creator": { "id": 1, "username": "amina", "role": "farmer", "profile": { "...": "..." } },
  "members": [{ "id": 1, "user_id": 1, "community_id": 1, "joined_at": "...", "member": { "id": 1, "username": "amina", "...": "..." } }]
}
```

**Errors:** 401, 409 (name already taken), 422 (missing `name`).

### `GET /api/communities/<id>`

No auth required. **200**: full detail, same shape as above. **404** if unknown.

### `PUT /api/communities/<id>`

Auth required, creator (or admin) only. Partial update. **200**. **Errors:** 401, 403, 404.

### `DELETE /api/communities/<id>`

Auth required, creator (or admin) only. Cascades to all membership rows. **204**. **Errors:** 401, 403, 404.

### `POST /api/communities/<id>/members`

Auth required (join). **201** `{"message": "Joined community."}`.
**Errors:** 401, 404, 409 (already a member).

### `DELETE /api/communities/<id>/members`

Auth required (leave). **204**.
**Errors:** 401, 403 (the creator cannot leave their own community — delete it instead), 404 (not a member).

## Conversations & Messages

All conversation/message endpoints require auth, and every one enforces
that the caller is a participant in that specific conversation (403
otherwise) — see `message_service._assert_participant`.

### `GET /api/conversations`

**200**: array of conversations the caller participates in, newest-active-first.

### `POST /api/conversations`

Body: `{"participant_ids": [2]}`. The caller is automatically included
even if omitted; duplicate ids are deduplicated.

**201 response:**

```json
{
  "id": 1,
  "created_at": "...",
  "updated_at": "...",
  "participants": [
    { "id": 1, "conversation_id": 1, "user_id": 1, "joined_at": "...", "participant": { "id": 1, "username": "amina", "...": "..." } },
    { "id": 2, "conversation_id": 1, "user_id": 2, "joined_at": "...", "participant": { "id": 2, "username": "brian", "...": "..." } }
  ],
  "messages": []
}
```

**Errors:** 401, 422 (empty/missing `participant_ids`, unknown user id(s), or only the caller's own id).

### `GET /api/conversations/<id>`

**200**: full detail, same shape as above (with `messages` populated).
**Errors:** 401, 403 (not a participant), 404.

### `GET /api/conversations/<id>/messages`

**200**: array of messages, oldest-first. **Errors:** 401, 403, 404.

### `POST /api/conversations/<id>/messages`

Body: `{"content": "..."}`.

**201 response:**

```json
{
  "id": 1,
  "conversation_id": 1,
  "sender_id": 1,
  "content": "Hey Brian!",
  "is_read": false,
  "created_at": "...",
  "sender": { "id": 1, "username": "amina", "role": "farmer", "profile": { "...": "..." } }
}
```

Sending a message bumps the parent conversation's `updated_at`, which is
what `GET /api/conversations`'s ordering relies on.

**Errors:** 401, 403 (not a participant), 404, 422 (missing `content`).

### `PATCH /api/messages/<id>/read`

Marks a message as read. Only a participant who is **not** the sender
can do this (you can't mark your own message as read).

**200**: updated message. **Errors:** 401, 403 (sender, or non-participant), 404.

## Example error responses

**404:**
```json
{ "error": "Post 999999 not found." }
```

**422 (validation):**
```json
{
  "error": "Validation failed.",
  "details": {
    "username": ["Length must be between 3 and 50."],
    "email": ["Missing data for required field."],
    "password": ["Missing data for required field."]
  }
}
```
